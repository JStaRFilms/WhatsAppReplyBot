## Nonblocking send interaction

### Gesture, identity and ownership

Use a small scoped intent collection in the existing client provider, with one conversation lane. It is not a background delivery service. The conversation screen owns composition; the provider owns submitted intents so a route change does not lose a pending request. Keep backend dispatch serialization and the current synchronous send response.

At the original Send or reaction gesture, before any hold/upload/storage await, capture a new intent containing service URL, accepted profile/account and binding epoch, conversation ID, monotonically increasing local gesture order, request UUID, composer revision, text/caption, quote ID and the selected image/audio reference. Allocate upload UUID separately when needed. Snapshot these values, do not reread current composition after awaits. Two deliberate identical sends have different intent IDs. Repeated taps on the same captured composer revision cannot create another intent; payload equality is not the duplicate rule.

Immediately show a local `Preparing` row, with no WhatsApp tick. Keep TextInput identity/focus, history scrolling, selection and swipe-to-quote usable. Persist a bounded local pending journal before clearing the captured composition or issuing an upload/send. Limit it to20 unresolved intents per service/account; if full or a storage write fails, keep the composition and report why submission stopped. Never evict unresolved entries to make room.

Journal only this owner's explicitly submitted action text, quote/upload/request IDs, scope, gesture order and local phase, under a separate service/profile/account storage key. Do not journal credentials, contact-book results, image base64 or audio bytes. Existing device storage is not an encryption claim. Text/quote recovery must survive remount/restart. Media gets an in-memory owned lease until completion; persist only a safe reference if the existing platform media lifetime supports it. After restart an unavailable attachment is labeled unavailable and needs explicit reattachment, never a reconstructed or automatic send. Do not delete a clip still owned by an intent when the composer unmounts.

After journal persistence, clear only the captured composer revision, including its quote/media. If typing or a new quote occurred meanwhile, leave it intact. This frees a fresh composer while the first intent uploads/sends. Composer occupancy for newer work remains acknowledged through the existing queue; clearing the old revision must not publish false empty occupancy for newer text. A local pending row does not mean takeover was acknowledged. Keep the existing explicit hold before media acquisition, and show unacknowledged pause honestly if that request fails.

### Ordering and result semantics

Within one client conversation, process upload and send in original gesture order. Do not let a later text overtake an earlier slow image. Other conversations may progress independently. Do not claim cross-device gesture order; server admission and existing dispatch lane determine that order. Revalidate scope and quote/source access before submission, with backend final checks unchanged.

| Evidence | Visible state and allowed progress |
| --- | --- |
| Local capture/persistence/upload | Preparing, Uploading or Waiting behind earlier message. No tick. Input/history/quote remain usable. |
| HTTP request outstanding | Sending, still no WhatsApp tick. Never disable unrelated composition. |
| Typed send result, outbox accepted | Accepted by transport, awaiting WhatsApp acknowledgment unless a receipt exists. End the intent's mutation wait immediately; request snapshot/history refresh separately. A slow/failed refresh is read feedback, not send failure. |
| Outbox queued/dispatching | Pending, not sent/delivered. Preserve request correlation while reading current status. |
| Network abort, unreadable response, scope loss after submission, unknown/partial | Outcome uncertain. Preserve request ID and recoverable content; do not retry, clear as success or free reservations. Stop automatic advancement of that conversation's later local intents. They remain visibly waiting, not dispatched. |
| Definitive pre-send validation/upload failure or failed/cancelled outbox | Not sent, with recoverable content. Local restore may fill an empty composer only after an explicit owner action, never overwrite newer work. No automatic retry. |

Use existing authenticated scoped snapshot reads to match `accountId + conversationId + requestId`, then outbox/component/transport IDs. A missing row is not proof that a request never executed. On restart or new binding, journal entries never resume mutations. Only same-profile authorized read reconciliation may update their status. Never rebind old requests to a new profile revision. Accepted evidence may resolve a lost HTTP response; merely seeing matching text cannot. Unknown accounting remains backend-owned even if a receipt later becomes visible.

No new automatic mutation retry, outbox cancellation endpoint or unknown-send override is included. Never discard a handed-off request. Locally never-submitted successors can be restored/removed explicitly without claiming transport cancellation. Existing backend owner-manual policy is unchanged; the client lane only prevents its own queued gestures from overtaking an unresolved predecessor.

Make `perform` return the validated mutation result once current-scope checks pass and schedule guarded refresh without awaiting it. Preserve action/domain/unknown errors independently of read errors, including dc99aa6 Assistant recovery. Audit every caller for any dependence on synchronous snapshot availability. Callers must use returned data or show pending until a read arrives, never infer refreshed state. Send intents need structured failures from the existing API path, not a swallowed `undefined` treated as failure proof.
