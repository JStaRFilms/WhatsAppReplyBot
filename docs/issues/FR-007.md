# FR-007: Outbox durability and unknown outcomes

## Requirement

Persist outbound intent, attribution and delivery evidence so recovery does not
blindly resend ambiguous actions.

This is a MUS v1 requirement. Its product behavior is planned, not verified
by this documentation task.

## Acceptance

- Use unique account/client request IDs, payload hashes, outbox component IDs,
  attempt IDs and transport IDs. Same request replay returns prior local
  result; conflicting reuse fails.
- Persist dispatching before transport handoff and check current authorization
  immediately before delivery. Recover unresolved dispatching as unknown.
- Distinguish positive transport acceptance from recipient delivery/read
  evidence. Count assistant units at positive acceptance, not on each receipt.
- Do not retry unknown results automatically or release their grant
  reservations. Reconcile only using reliable transport evidence.
- Report partial reaction/text outcomes per component. Never retry a whole
  bundle because one component failed or timed out.
- An owner-authorized retry of an unknown action uses a new ID and explicit
  duplicate-risk acknowledgment. No distributed exactly-once claim.

## Contracts

outbox, outbox_components, api_requests, transport_message_id and
delivery_state. outbox.changed/delivery.changed; pre-handoff transaction and
reconciliation boundary.

Use [Assistant_Architecture.md](../features/Assistant_Architecture.md) as the
shared schema and API/event contract. See the
[requirements index](../Project_Requirements.md) for scope and precedence.

## Verification

Fault-inject around commit, handoff and acknowledgment with fake transport.
Later controlled sends must test real echoes, receipt evidence and unknown
reconciliation under separately approved recipients/actions.

The evidence gates and test matrix are in
[Verification_Plan.md](../Verification_Plan.md). No live test is authorized
by this issue.

## Out of scope

Blind retries, guaranteed recipient delivery, read-receipt transmission in the
spike and live sends without authorization.
