# FR-009: Scoped memory and authentic style

## Requirement

Persist history separately from a small bounded prompt. Use
account/contact-scoped source-linked facts, commitments, summaries and
authentic owner style.

This is a MUS v1 requirement. Its product behavior is planned, not verified
by this documentation task.

## Acceptance

The [context and writing-profile follow-up](../features/Conversation_Context_and_Writing_Profile.md)
records the owner's requested next direction, proposed defaults and focused
acceptance checks. Consult it before implementing this issue; the fixed budget
and component limits below belong to the earlier design. New context limits
require provider verification, not an assumption that 256k is available.

- Enforce the architecture's total 8,000 input-token budget and component
  limits. Required-input overflow returns needs-owner rather than dropping
  policy.
- Retrieve only the current account/contact. Global style contains sanitized
  approved instructions and explicitly selected authentic examples, not another
  contact's private chat.
- Distinguish owner_written, assistant_written, owner_edited_assistant,
  contact_written and unknown. Unedited AI and unknown output never train owner
  style.
- Facts and media interpretations stay inferred unless the owner confirms them.
  Every derived record links to eligible same-contact source IDs.
- Corrections increment revisions. Deleting a source invalidates/removes
  dependent memory/examples and pending context work. Exclusion blocks all AI
  retrieval.

## Contracts

messages authorship, memories certainty/revision/source_message_ids_json,
style_examples and draft context_source_ids_json. PUT/DELETE memories and
history deletion contract.

Use [Assistant_Architecture.md](../features/Assistant_Architecture.md) as the
shared schema and API/event contract. See the
[requirements index](../Project_Requirements.md) for scope and precedence.

## Verification

Test provenance filters, cross-account/contact retrieval, budget overflow,
global-example consent and deletion cascades. Provider tokenization and
response quality need later approved model tests.

The evidence gates and test matrix are in
[Verification_Plan.md](../Verification_Plan.md). No live test is authorized
by this issue.

## Out of scope

Vector databases, bot-output style training, unlimited history prompts and
cross-contact private retrieval.
