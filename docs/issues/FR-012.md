# FR-012: Windows service and adapter feasibility

## Requirement

Operate as one Windows Node service with SQLite and an eventual Expo client.
Evaluate Baileys honestly behind the normalized boundary before production
activation.

This is a MUS v1 requirement. Its product behavior is planned, not verified
by this documentation task.

## Acceptance

- Keep Windows awake/connected as an operating requirement. Report
  disconnected/connecting/connected/degraded and last observation time; Expo is
  not the always-on backend.
- Use OpenRouter openai/gpt-6-luna for the app after authorized model tests.
  Recheck current limits/availability/price rather than relying on intake
  evidence.
- Start with authenticated secure local-network access only. No public endpoint
  or commercial deployment. Owner-device credentials are separate from WhatsApp
  identities.
- Create only the later approved self-contained offline spike in
  prototypes/whatsapp-assistant/, using fake model/transport by default and
  independent dependencies.
- Capability reports mark supported/unsupported/unverified with evidence.
  Required unverified source/identity/delivery behavior blocks production
  automation.
- Pairing, read-only probes, model costs and sending each need explicit
  approved steps. Passing offline tests does not unlock UI/UX Design or live
  activation.

## Contracts

transport_state capability_json, adapter observation/handoff/reconciliation
boundary and owner_devices. See Builder_Prompt.md and Verification_Plan.md for
phase gates.

Use [Assistant_Architecture.md](../features/Assistant_Architecture.md) as the

## Verification

Offline startup/restart and fake capability tests prove fail-closed local
behavior. Controlled device tests establish Baileys observations; separately
approved provider tests establish actual model behavior.

The evidence gates and test matrix are in
[Verification_Plan.md](../Verification_Plan.md). No live test is authorized
by this issue.

## Out of scope

Expo UI before approval, product scaffold in Genesis, public hosting,
schedules, commercial billing, generalized plugins and changes to CreativeOS
dependencies.
