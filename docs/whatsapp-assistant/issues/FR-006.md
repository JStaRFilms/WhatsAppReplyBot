# FR-006: Manual takeover and explicit resume

## Requirement

Give the owner durable control over a conversation. App typing requests pause,
and an observed manual owner send from any linked client invalidates assistant
work.

This is a MUS v1 requirement. Its product behavior is planned, not verified
by this documentation task.

## Acceptance

- Pause acknowledgment follows the durable manual-control transaction. A
  disconnected client reports unacknowledged rather than paused.
- Pause and app manual send advance workflow_version, revoke the active grant
  and cancel queued assistant work before new handoff.
- Match known assistant transport IDs before interpreting account-outbound
  messages. Unmatched owner/unknown outbound observations conservatively take
  over.
- Manual control survives restart and new inbound messages. Timers, expiry and
  assistant suggestions never resume it.
- Explicit confirmed resume validates the current version and invalidates stale
  work. It does not restore revoked grants or authorize old drafts.
- Show the cancellation boundary. Work already handed to WhatsApp may still
  deliver even after a pause acknowledgment.

## Contracts

conversations control/workflow_version, delegations and outbox_components. POST
pause/manual-send; confirmed resume owner-action; control.changed.

Use [Assistant_Architecture.md](../features/Assistant_Architecture.md) as the
shared schema and API/event contract. See the
[requirements index](../Project_Requirements.md) for scope and precedence.

## Verification

Reopen SQLite after pause; test stale completions, assistant echoes, unmatched
linked-client sends and pause/handoff races. Native WhatsApp typing observation
is optional and unverified.

The evidence gates and test matrix are in
[Verification_Plan.md](../Verification_Plan.md). No live test is authorized
by this issue.

## Out of scope

Implicit resumption, guaranteed cancellation after handoff and native-client
typing as a mandatory capability.
