# FR-008: Live processing and attention review

## Requirement

Process live events rather than periodically replying to history. Provide a
read-only time-window digest of unanswered, important, draftable and
owner-responsibility conversations.

This is a MUS v1 requirement. Its product behavior is planned, not verified
by this documentation task.

## Acceptance

- Persist dedupe keys, adapter cursor and sync phase. Normalize every
  observation as live/backfill/replay/unknown.
- Backfill/replay/unknown can populate history and review, but cannot auto-send
  or automatically draft old messages. An owner may explicitly request
  historical drafting.
- Repeated live events and assistant echoes cannot create duplicate actions.
  After restart or uncertain reconnect, block automation until a reliable live
  boundary exists.
- Digest results include source IDs, reasons, responsibility and
  incomplete-history flags. A reaction alone does not prove an obligation
  fulfilled.
- Excluded contacts can appear as owner-only activity counts, never
  model-processed content. Review itself sends nothing and changes no
  permissions.

## Contracts

processed_events, transport_state, event_log, messages source and POST reviews.
GET events supports ordered sequence recovery or snapshotRequired.

Use [Assistant_Architecture.md](../features/Assistant_Architecture.md) as the
shared schema and API/event contract. See the
[requirements index](../Project_Requirements.md) for scope and precedence.

## Verification

Test duplicate batches, live boundary loss, initial backfill, replay restart
and digest candidates with synthetic history. Device evidence must establish
which adapter fields identify sources and dedupe IDs.

The evidence gates and test matrix are in
[Verification_Plan.md](../Verification_Plan.md). No live test is authorized
by this issue.

## Out of scope

History auto-reply scans, guaranteed complete synchronization and deferred
completion-report workflows.
