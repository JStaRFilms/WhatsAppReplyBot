# FR-010: Media context and status replies

## Requirement

Use accessible image, sticker and GIF context with bounded analysis.
Distinguish direct replies to the owner's status from ignored status
broadcasts.

This is a MUS v1 requirement. Its product behavior is planned, not verified
by this documentation task.

## Acceptance

- Use actual accessible image/sticker content with text context. Animated
  sticker/GIF understanding uses up to three representative frames per item
  within six-frame/two-item/5 MiB/1,024-pixel limits.
- Future GIF display includes playback, not GIF search, generation or
  autonomous media sending.
- Resolve DM status replies to accessible quoted/original status text or media
  when available. Mark missing/expired originals explicitly; never invent
  content.
- Status broadcasts and groups do not trigger automatic replies. A resolved
  direct status reply follows the contact's ordinary permissions.
- View-once/disappearing content is not retained or exported by default. Expiry
  defeats ordinary cache retention.
- Unsupported/oversize/missing media uses explicit text-only fallback or
  needs-owner when meaning depends on content. Do not analyze historical
  attachments in bulk.

## Contracts

media_items access/expires_at/view_once, messages
quoted_message_id/status_reference and conversation kind. Model media limits
count toward bounded input.

Use [Assistant_Architecture.md](../features/Assistant_Architecture.md) as the
shared schema and API/event contract. See the
[requirements index](../Project_Requirements.md) for scope and precedence.

## Verification

Synthetic fixtures prove classifications and fallback. Read-only authorized
device checks must establish actual media access/status metadata. Paid vision
understanding and eventual GIF playback require separate tests.

The evidence gates and test matrix are in
[Verification_Plan.md](../Verification_Plan.md). No live test is authorized
by this issue.

## Out of scope

Voice notes, full attachment parity, permanent descriptions of every file,
status publishing and media generation.
